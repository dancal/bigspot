# 엉덩이·머리 쪽 흔들기

2026-10-09. 기존 120 BPM과 대각선 스텝 간격 0.5초를 유지한다. 기본 요청 이름과 버튼은 그대로 `dance_funk`, 버튼 5 유지 + 12다.

## 추가한 동작

| 구간 | 방식 |
|---|---|
| `hip_wiggle` | 회전 중심을 앞쪽으로 옮겨 뒤쪽 몸체를 좌우로 비틀고 roll을 겹침 |
| `head_shake` | 회전 중심을 뒤쪽으로 옮겨 앞쪽 몸체를 좌우로 흔듦 |
| `head_bob` | 같은 뒤쪽 중심을 사용해 앞쪽 몸체를 위아래로 끄덕임 |

**모델에는 목 관절이 없다.** 머리 쪽 움직임은 몸통과 다리로 표현하며 머리만 독립적으로 돌리지 않는다. CAD/URDF의 앞·뒷다리 첫 관절 위치 평균을 기준으로 삼는다. 빠르게 발을 교대하는 좌우 비틀기에서는 회전 중심을 그 기준의 40% 위치로 몸통 안쪽에 잡아 무게중심 이동을 줄인다. 끄덕임은 뒤쪽 기준을 사용한다. `P - R P`의 몸체 이동을 관절 IK에 함께 적용해 앞쪽 또는 뒤쪽 움직임을 강조한다. 몸체 위치를 물리 엔진에서 강제로 바꾸지 않는다.

제자리 리듬 → 엉덩이 흔들기 → 머리 쪽 좌우 → 끄덕임 → 좌우 셔플 → 앞뒤 스텝 → 턴 → 혼합, 각 8박자다. 시작·종료를 포함한 계획은 35초다. 엉덩이·머리 쪽 좌우 비틀기는 네 박자, 끄덕임과 기존 몸체 리듬은 두 박자 주기이며 발 교대는 한 박자다. 구간 마지막 두 박자에는 다음 동작을 부드럽게 겹친다. IMU는 안무의 목표 roll/pitch와 실제 기울기의 차이를 보정한다.

관절 한도와 명령 속도 한도 3.8 rad/s, 기존 토크·속도·30 A 전원 모델과 센서 시작·중단 조건을 유지한다. 보행 주기는 그대로 1초이며, 지면 지지 비율을 0.65에서 0.67로 늘리고 계획 발 들기 높이는 26에서 24 mm로 조정했다. 회전 경로·구간 연결·동작별 앞/뒤 움직임을 코드 검사로 확인하고 실제 ROS 물리 기록에서 다시 측정한다.

지원 발 두 개 미만이 64 ms보다 오래 지속되면 복귀한다. ROS 시계 차이 계산에서 64 ms가 `0.064000000000001`로 표현되어 조기 중단되는 오류를 재현했다. 1 ns의 수치 오차 여유로 경계를 일치시켰다. 80 ms의 지지 부족은 계속 복귀를 요청한다. 중단 원인도 상태·완료 기록에 남긴다.

## 재현과 기록

정상 ROS 물리 기록의 움직임은 다음과 같다. 앞/뒤 몸체 기준점은 실제 몸체 위치·자세로 변환한 CAD 관절선의 중점이며, 관절 목표가 아니다.

| 동작 | 강조한 쪽의 실제 이동 폭 | 반대쪽의 실제 이동 폭 |
|---|---:|---:|
| 엉덩이 좌우 | 뒤쪽 7.0 cm | 앞쪽 4.0 cm |
| 머리 쪽 좌우 | 앞쪽 6.2 cm | 뒤쪽 2.8 cm |
| 끄덕임 | 앞쪽 위아래 3.8 cm | 뒤쪽 위아래 0.9 cm |

주 안무 32초에서 대각선 쌍 스텝 63회, 중앙 간격 0.504초를 측정했다. 질량 +15%·마찰 0.55·자이로/가속도 잡음 조건에서는 60회·0.496초였다. 두 조건 모두 넘어짐 없이 안정 확인 후 약 35.4초에 READY로 완료했다.

접촉 힘 >1 N인 발 두 개 이상이 관측된 비율은 기본 98.90%, 별도 조건 98.35%다. 전체 지면 접촉 힘 <1 N의 최장 시간은 각각 12·10 ms였다. 계속 두 발 지지를 유지했다는 뜻은 아니며 실물 안전 검증도 아니다.

최종 실제 ROS 시험 9개를 통과했다. 정상·별도 조건·버튼 실행 3개, 중지·데드맨 해제·초음파 단절 복귀 3개, IMU·관절·접촉 정보 단절 3개다. 춤 중 관절 명령 최대 속도는 정상 3.44, 별도 조건 3.56 rad/s로 춤 한도 3.8 rad/s 이하다. 일반 기립·보행의 기존 한도는 4 rad/s다.

중지 복귀는 1.5초 몸체 경로가 끝난 뒤 발 접촉·관절·기울기·자이로 안정 조건을 확인하고 READY로 넘어간다. 몸체 경로가 남아 있는데 센서가 먼저 안정됐다고 정상 제어로 넘기던 연결을 수정했다. 중요 센서 단절은 IMU 약 224 ms, 관절 약 208 ms, 접촉 약 96 ms에 FAULT가 됐고 이후 각도 명령 변화는 0이었다. 마지막 각도 유지이며 전원 차단은 아니다.

정상 기록에서 추정 30 A 전류 제한이 작동한 비율은 약 0.69%다. 실제 전류 측정값은 아니다. 과도한 무게중심 이동으로 중단된 초기 시도는 로컬 시험 폴더에 보존했으며 배포 압축 파일에는 최종 ROS 기록을 넣는다.

```bash
bash simulation/tools/run_funk_ros_demo.sh --output-folder groove
python simulation/tools/make_funk_report.py --output-folder groove
python simulation/tools/render_funk_recording.py --output-folder groove
ros2 topic pub --once /bigspot/action std_msgs/msg/String "{data: dance_funk}"
```

`generated/groove/`에 ROS CSV·센서 JSON·검증 JSON/PNG·정상 속도 영상을 저장한다. `dance_funk.mp4`는 37초다. 영상은 실제 몸체·관절 측정 기록과 두 고정 시점을 사용하며 원래 120 BPM 합성 음악을 포함한다. 미리보기는 새 세 동작의 12초 발췌다. 전체 코드 검사 95개와 ROS 패키지 빌드를 통과했다.

로컬 ROS 2 Humble + MuJoCo CPU 결과다. 실제 질량·전류·IMU 정확도·전체 자체 충돌·실물 구동·Isaac GPU 실행은 미검증이다. ROS 1 실물 PWM 경로에는 연결하지 않았다. 이전 측정과 모델 한계는 [빠른 스텝 춤 기록](FUNK.ko.md)을 따른다.
