# 빠른 스텝 춤 검증

2026-10-09. 실행 환경: 로컬 ROS 2 Humble + MuJoCo 3.15 CPU.

이 문서는 5구간 빠른 스텝 춤을 추가한 당시 기록이다. 현재 `dance_funk`에는 [엉덩이·머리 쪽 흔들기](GROOVE.ko.md) 3구간을 추가했다. 현재 결과 경로는 `generated/groove/`이며 아래 `generated/funk/` 결과는 이전 기록으로 보존한다. 현재 재현 도구는 8구간 안무를 실행한다.

이전 `dance_steps`는 한 발의 체중 이동·탭·착지·복귀에 5.67초를 썼다. 새 기본 `dance_funk`는 **120 BPM, 0.5초마다 대각선 두 발을 교대**한다. 박수와 이전 몸체 춤은 선택 목록에 유지했다.

## 자료에서 적용한 기준

[Spot 공식 동작 문서](https://dev.bostondynamics.com/docs/concepts/choreography/move_reference.html)는 한 박자 스텝, 두 박자 몸 흔들기와 제자리 달리기 동작을 설명한다. [Spot 안무 설계 설명](https://bostondynamics.com/blog/in-step-with-spot/)의 몸체·다리 트랙을 겹치는 방식을 참고했다. BigSpot에는 자체 IK·보행·센서 제어기로 적용했다. Spot 제어기나 성능을 가져온 것은 아니다.

[Petoi 자세 제어 설명](https://docs.petoi.com/applications/skill-creation)의 동작별 목표 roll/pitch를 참고했다. 춤에서 자이로 보정은 항상 수평으로 돌아가려는 방식이 아니라 **안무가 요구하는 기울기와 실제 기울기의 차이**를 줄인다. 음악 인식은 없으며 지정한 BPM으로 실행한다.

## 안무와 측정

시작 2박자 → 제자리 리듬·좌우 셔플·앞뒤 스텝·턴·혼합 각 8박자 → 종료 4박자. 계획 23초, 정상 ROS 기록은 자세 안정 확인 후 약 23.4초에 완료했다. 한 발의 전체 주기는 1초, 대각선 쌍의 교대 간격은 0.5초다. 몸체는 두 박자 주기로 움직이고 구간 전환·종료에는 가속·감속을 적용한다.

| 항목 | 실제 ROS 물리 기록 |
|---|---:|
| 주 안무 20초의 대각선 쌍 스텝 | 39회, 중앙 간격 0.500초 |
| 주 안무의 개별 발 착지 | 80회 |
| 좌우 셔플의 몸체 좌우 이동 폭 | 7.9 cm |
| 앞뒤 스텝의 몸체 전후 이동 폭 | 12.9 cm |
| 턴 구간의 yaw 변화 폭 | 39.4° |
| 네 발의 최대 바닥 높이 | 26.0~35.4 mm |
| 전체 roll / pitch 변화 폭 | 8.3° / 7.5° |
| 관절 명령 최대 속도 | 정상 3.49 rad/s, 한도 3.8 rad/s |

착지는 발 높이 >10 mm와 낮은 접촉 힘을 확인한 뒤 실제 접촉 힘 >1 N이 연속 관측될 때 센다. 목표 좌표만으로 세지 않는다. 제자리 구간에서도 다리를 교대로 들어 올린다.

세 발로 정지 자세를 버티는 방식에서 대각선 지지의 동적 보행으로 바꿨다. 접촉 힘 >1 N인 발이 두 개 이상인 기록 비율은 기본 98.88%, 별도 조건 98.48%다. 2 ms 물리 시간 단위로 검사한 전체 지면 접촉 힘 <1 N의 최장 구간은 각각 0 ms와 2 ms다. 항상 두 발 지지를 유지했다는 뜻은 아니다.

## 센서·중단 검증

실제 ROS 시험 **9개**, 전체 코드 검사 **91개**를 통과했다. 정상·질량 +15%/마찰 0.55/자이로·가속도 잡음 조건·버튼 실행 3개, 중지·데드맨 해제·초음파 단절 복귀 3개, 중요 센서 단절 3개다.

IMU·관절·발 접촉 정보 단절은 각각 약 208·208·96 ms에 FAULT로 전환했다. 이후 관절 각도 명령 변동은 0이었다. 이는 마지막 명령 유지이며 전원 차단은 아니다. 중요 피드백이 없는 상태에서 착지를 확인했다고 처리하지 않는다.

시작에는 정지한 READY, 유효 IMU·관절·네 발 접촉·초음파 여유 0.30 m 이상과 정상 기립 자세가 필요하다. 초음파 장애물·입력 해제·일반 중지는 속도를 줄이고 발 착지와 자세 안정을 확인한 뒤 READY로 복귀한다. 검증한 BPM은 120이다. 다른 BPM은 실험 활성화가 필요하다.

RDS5160 ×12, 7.4 V / 30 A 토크·속도·전류 모델을 적용했다. 정상 기록에서 추정 총전류 한도가 작동한 시간은 약 1.17%다. 실제 전류·질량·서보 영점은 측정하지 않았다. 이상적인 자세 quaternion을 사용했고 전체 자체 충돌 검사는 꺼져 있다. 따라서 **실물 안전·실물 IMU 정확도·Isaac ROS 5 GPU 실행·새 신경망 학습 결과는 미검증**이다. ROS 1 실물 PWM 경로에는 연결하지 않았다.

## 조이스틱과 재현

일반 ROS Joy 인덱스다. **5 유지 + 12 빠른 춤 / 8 앉아서 박수 / 13 애교**, 1 정지. **5 + 4 + 12/13** 이전/다음 선택, **5 + 4 + 6** 실행. 목록은 30종이다. 실제 게임패드 버튼 이름·번호는 미확인이다.

```bash
bash simulation/tools/run_funk_ros_demo.sh
python simulation/tools/make_funk_report.py
# 센서·관절 피드백을 제공하는 시뮬레이터에서 요청
ros2 topic pub --once /bigspot/action std_msgs/msg/String "{data: dance_funk}"
```

`generated/funk/dance_funk.mp4`는 25초, 20 fps, 정상 속도 영상이다. 직접 합성한 120 BPM 드럼·베이스를 넣었다. `funk_preview.gif`는 셔플·앞뒤·턴·혼합 구간 16초다. 실제 ROS의 몸체 위치·관절 측정 기록을 고정 카메라로 렌더링했고 배속이나 몸체 이동값 수정은 없다. `funk_validation.json/png`, `ros_*.csv`, 센서 JSON에 측정값을 보관한다.
